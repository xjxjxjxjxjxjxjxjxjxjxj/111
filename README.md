# 机械狗自主阶段闭环版 dog11（当前最新版）

本目录从学长版代码继续改造，但已经删除会让机械狗“不看道具、只按固定秒数走”的主流程。
所有关键动作都由当前相机观测触发；四足离散动作切换后统一等待 `0.6 s` 再观察。

## 已确认的正式流程

1. 沿约 20 mm 黑色引导线前进，机身保持在黑线左侧并提高到 `forward_speed=12`。
2. 每方只有一个信息立牌，现场随机为黄色或黑色，二选一。
3. 由 50 mm 圆牌的视直径估算狗前端到立牌的距离；连续 5 帧处于 `20±2.5 cm` 才报警。
4. 黑牌：继续视觉循线，同时机械臂上下挥舞 5 秒击倒牌；之后不再寻找第二块牌。
5. 黄牌：右移、前行、左移绕开，之后用相机重新找到并居中黑线；之后不再寻找第二块牌。
6. 路牌完成后继续循线。黑线连续从画面下方消失且球稳定出现时进入球区。
7. 第一次球区观测按标定距离选择最近球并锁色，同时保存另外两球的最近观测作为搜索提示。
8. 每个球都执行“俯身观察→一次短步修正→四足站稳→重新观察”，连续两批对准才夹取。
9. 三个球使用各自的成功抓取照片标定；任何球都不能借另两球的位置推算抓取点。
10. 持球后重新识别3倍杯杯口椭圆并短步闭环对准；红、绿、蓝三球全部投3倍杯。
11. 最后一球投放结束后先后退2秒、原地转90度；若仍看到球或杯，再转45度并重新观察。
12. 返程只锁定原黑色引导线。右侧赛区边界候选会被排除，圆弧只作为首次锁线的辅助证据。
13. 进入长方形出发区时，必须先看到两条横向黑边，再等两条黑边在全画幅内都连续消失后停车。

## 路牌物理标定

`camera_geometry.json` 使用黄色路牌的 20 cm、30 cm 共 6 张照片拟合：

- 有效焦距：约 `171.73 px`；
- 相机到机械狗前端的安装偏移：约 `2.66 cm`；
- 拟合均方根误差：约 `0.52 cm`。

不能只用 20 cm 单点，因为比赛中的 20 cm 是“狗前端到牌”，针孔模型原始距离是“相机到牌”。
黑牌会与暗色墙带粘连，因此采用圆弧、圆内暗度、外围亮度和竖直支架联合检测；12 张已测距路牌照片均正确分色，30 cm 样本不会进入 20 cm 门限。

重新生成标定参数：

```bash
python calibrate_sign_distance.py \
  --sample calibration_images/sign_yellow_20cm 20 yellow \
  --sample calibration_images/sign_yellow_30cm 30 yellow \
  --validate calibration_images/sign_black_20cm 20 black \
  --validate calibration_images/sign_black_30cm 30 black --write
```

## 三色球闭环

`ball_config.json` 中的 `alignment.profiles` 分别保存蓝、绿、红球抓取窗。蓝球只读取蓝球照片，红球只读取红球照片，绿球只读取绿球照片；背景中的另两球不会参与目标坐标计算。

`BallSceneMemory` 会锁定最近球，并保存其余球的 `(颜色、x、y、半径、估算距离、时间)`。保存值会过期，且只能帮助下一次转动相机寻找；每次四足移动前仍必须重新识别。

单球硬件测试只抓起并保持，不会盲走到杯子：

```bash
python ball_grab_test.py green
```

## 杯口与返程状态

四张“放球位置”照片已建立杯口椭圆目标窗，四种曝光均能被 `cup_vision.py` 识别为已对准。投杯策略已确认为三个球全部投3倍杯。

新增的3张返程途中照片和3张进入出发区照片已保存到 `calibration_images/return_path` 与 `calibration_images/start_zone_entry`。`return_home_vision.py` 采用两层保护：

- 返程主线：排除贴右图边的赛区边界；首次锁线需要圆弧辅助证据；锁定后若候选位置突跳则停车，不能换到右边界继续走。
- 出发区：先连续看到长方形的两条横向黑边，之后只有全画幅内两条边都连续5帧消失才算完成；左、右残留或斜线残留都会阻止停车判定。

当前仍保留安全锁：

- 缺少“球成功落入杯中后”的相机照片，尚未验证投放后的视觉确认；
- 返程视觉已通过照片离线测试，但还没有在机械狗连续移动的视频流上验证，尤其缺少偏左/偏右进入出发区的连续照片。

因此当前可以安全测试路牌、球识别、单球闭环抓起、杯口预对准和返程视觉观察，但完整三球自主程序仍不会启用释放与返程电机动作。

规则场地图已保存为 `rule_reference/word/media/image1.png`。程序只把它转写为 `course_layout.json` 的拓扑顺序，不会把俯视示意图与低位相机画面直接模板匹配。返程将依赖实时黑线和运行开始时记录的真实出发区视觉特征。

## 主要文件

- `sign_line_closed_loop.py`：当前可运行的单立牌循线测试。
- `line_sign_config.json`：循线、单随机立牌、20 cm和动作参数。
- `camera_geometry.py/json`：路牌与球共用的物理距离模型。
- `ball_vision.py`：三色球检测、多帧稳定、最近球锁定和位置提示记忆。
- `ball_closed_loop.py`：分颜色抓球短步闭环。
- `cup_vision.py`：杯口椭圆检测与短步闭环。
- `course_memory.py` / `course_layout.json`：规则场地图的拓扑记忆与状态约束。
- `return_home_vision.py` / `return_home_config.json`：返程主线防误锁与出发区双横线完成判定。
- `autonomous_senior_v4.py`：学长版硬件动作辅助库，旧定时主程序已禁用。
- `AI_CONTEXT.md`：供其他 AI 继续修改时优先读取。
- `VERSION.json`：标明最新版、已标定能力和仍未解除的安全锁。
- `run_recording.py`：使用控制程序正在处理的同一相机帧录像并写 JSONL 遥测，避免第二个进程抢占摄像头。
- `automation/`：OpenCode 部署/收集、Codex 分析/改版、300 秒后每 100 秒检查以及 GitHub 交接所需的本地工作流。

若OpenCode的PATH找不到`codex`，无需依赖npm；`workflow_config.json`中的`codex.executable=auto`会自动定位Codex Desktop内置CLI。可先运行`python automation/workflow_controller.py doctor --config <配置文件>`验证实际路径和版本。
